2026-09-25 mechanism audit (legasus/screen/MECHANISM-AUDIT.md, instrument server/mechanismAudit.mjs):

- Earliest divergence between arms is the FIRST model action: treatment edit_file 25/30, control run_python 24/30.
- The first edit decides the unit: every "up" first edit ended RETAIN; of 13 bad first edits only 1 recovered (not accepted). After a bad edit the model re-issues the same edit and the repeat guard ends the run.
- "Treatment used less time" was a control artefact: 7 control units burned 299s on backend hangs.
- 8/15 vs 2/15 across replicates: NO sampling seed was ever sent; first turns differ only in the sampled BUILD PLAN. "Same seeds" in earlier records meant seed FILES.
- Labels vs bytes: 0 disagreements in 89 units; isolation held (control saw 0 diagnostics).
- Fixed: runner hard-coded "AUTODIAG-1" name; mangled /rd+$/ regex; untimed COMPLETE; scripted stop waited on client exit (~5 min) -> server/gpuWatchdog.mjs (detached, sentinel or deadline, OBSERVES stopped, tested 28/28).
- New: AGENT_SEED -> options.seed (vLLM honours it: seeded pair byte-identical in the probe); diagnosticMessage mode 'summary' (counts only) for a NOTIFY arm.

**Why:** the "fewer calls + less elapsed + more repairs" combination is CONSISTENT WITH one account (first-action shift) - association, not demonstrated cause (a good first edit may mark an easier task or a better plan). Missing seeds explain why replicates were uncontrolled, NOT the size of the 8-to-2 swing (seeded MECH-1 still showed 5 vs 8). "Semantic content" is a BUNDLE (examples, expected outputs, localization, task framing); counts-only removed all at once, so no component is isolated. tatte 2026-09-25: the evidence looks like a better initial PROBLEM SPECIFICATION, not a working recovery loop - two different capabilities.

**How to apply:** for any repeat/variance claim, check whether a sampling seed was actually SENT and honoured; separate "told that tests fail" from "told which cases fail" before crediting content (MECH-1, arms CONTROL/NOTIFY/AUTODIAG_ARM, seeds 101/202, frozen in MECH-1_DEFINITION.md). **EVAL-1 (2026-09-26): INCOMPLETE - hung after 21/88 units for 2 h.** Docker on the host stopped returning from containers (~04:01Z); caseSet.js had NO host-side timeout; that wait is in post-processing OUTSIDE the per-unit wall; the campaign deadline was only checked between units; the supervisor only reacted to an exit. The GPU watchdog stopped the app at its deadline (~$3.0-4.3 spent, ~$2.2-3.2 idle). Fixed + tested without spend: caseSet host timeout + named container force-removed; campaign-level wall armed BEFORE the loop (INTERRUPTED row for the in-flight unit, UNATTEMPTED for the rest, exit 3); supervisor stall-kill by pid + resume. Side finding: exit 127 in this shell = EXTERNAL termination (verified by Stop-Process), so OVERNIGHT-1 attempt 1 was killed from outside, source unknown. Lesson: every await that can touch docker needs a host-side timeout, and bounds must exist at unit, campaign, supervisor AND provider layers. EVAL-1 unanswered; re-run needs new authorization.
