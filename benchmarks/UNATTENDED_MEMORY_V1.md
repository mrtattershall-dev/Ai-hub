# Unattended memory policy, 2026-10-21

REL-1's original collector was stopped after an Ollama OOM left s101 control interrupted. REL-2's chain was stopped before launching. Original workspaces, transcripts and partial results remain in data/gather and the frozen worktrees. These interrupted data do not establish a model-quality comparison.

Operational collection resumes against the current product runtime in data/gather-memory-v1, seeds 1001 onward, five goals per session. This is reliability collection, not a continuation of the preregistered REL-1 or REL-2 comparison. The settings differ: 8192-token context, one real local inference call or browser-heavy maintenance batch at a time, 512 MB Docker command workers, bounded model/hub processes and automatic recovery. Any future comparison must preregister these conditions for both arms.

The machine has about 7 GB RAM. An additional 12 GiB swap file gives 16 GiB total swap. Ollama is limited to 4 GiB RAM plus 8 GiB swap, with a 3 GiB soft limit, one loaded model and one parallel request. The Legasus user service slice is limited to 2 GiB RAM plus 2 GiB swap. Swap deliberately trades speed for continued operation; physical RAM is still finite and unrelated desktop programs can still exhaust the machine.

Run recovery preserves the run ID, workspace and history. It waits for the daemon to answer, backs off and allows six persisted recovery attempts per run. It does not approve commands or create replacement owner tasks. The collector stops a run after exhaustion, records infrastructure failure and advances; its global backstop remains 270 minutes per goal. A crashed collector is restarted by systemd and reconciles the unfinished goal with the hub's persisted run, avoiding duplicate starts. Atomic per-goal result files are authoritative; sessions.jsonl is a convenient aggregate and can miss its final append if the collector dies exactly after writing a result.

Fuzzing uses one-seed batches with the existing alternating goal/hostile schedule and resumes from its last completed batch. Its recorded identities and results are retained. Inspector waits on the same resource lock and unloads Ollama before heavy tests; model-backed per-run Watcher reviews retain the existing $10 budget. A process waiting for resources is reported as waiting, not productive inference.

Install on another Linux machine with scripts/install-memory-guard.sh (root) and scripts/install-unattended.sh (user), after installing this project's dependencies, Docker worker and the model. The conservative limits work as a starting profile; inspect that machine's RAM and storage before increasing them. Chromebook firmware and Linux support must be checked for its exact hardware.

Validation: modelBudget.test.mjs passed 13 checks; resumeAfterRestart.test.mjs passed seven. unattendedRecovery.test.mjs passed admission/serialization/cancellation, bounded retry and real hub dropped-connection recovery checks. A real 4B smoke request returned OK. An intentional collector SIGKILL caused a systemd restart with the same run ID. An intentional Ollama SIGKILL caused its automatic restart; the operational collector then resumed that same run. Final live inspection confirmed qwen3.5:4b with an 8192-token context, the model holding the resource lease, and the fuzzer waiting. This is recovery validation, not an overnight soak result.
