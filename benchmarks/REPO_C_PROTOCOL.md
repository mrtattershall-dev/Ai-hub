# Repo C — prospective benchmark protocol

Frozen with `legasus-freeze-r3`, **before Repo C is chosen**. Nothing in this document may be changed
once the first Repo C task is run. If it needs changing, the run is burned.

## Why architecture work stops here

Legasus has become powerful enough to explain and adapt to almost anything shown to it. Seven laws, an
authority calculus, an adjudicator and an anti-explanation control were all derived from `packaging`,
which means further internal refinement without fresh falsification is overfitting rather than progress.
The next source of information has to be reality outside the architecture.

**`packaging` is burned for prospective validation.** It taught LegaExercise, behavioural regions, stale
evidence, the `history` dimension, specification mutation, Frankenstein joins and most of the laws. It
remains excellent development material and it can never again be a headline result.

## What is frozen

Code, tests, the ontology (observability states, scope dimensions, admitted dimensions and their relevance
arguments), the adapters, the scoring rules, the exclusion rules, the model and its sampling parameters,
the budget, and the verdict criteria below. Verified by `legasus/legaknow/FREEZE-GATE.test.mjs`:
10 historical defects refused with no special-case recognition, 9 legitimate operations still admitted,
and both `GENUINE_DISAGREEMENT` and `QUIESCE` reachable.

## Choosing Repo C

Eligibility may be established **before** the freeze and must be boring: language, runnable environment,
size range, and the presence of an externally authored verifier or test suite. Candidate failures,
specific semantics, and anything that could tune Legasus to the target may **not** be inspected.

Repo C must supply two independent things:

    repository behaviour        +        externally authored evidence

Legasus must not control how all of the target's truth is produced.

## The four measurements, reported separately and never summed

| | |
|---|---|
| **CAPABILITY** | of supported cases, how many does it actually repair or extend? |
| **COMMIT PRECISION** | of states it permits to persist, how many satisfy the independent target? |
| **COVERAGE** | how much of the eligible surface can it obtain enough authority to act on at all? |
| **EPISTEMIC CALIBRATION** | when it refuses, contests, declares incomparable or quiesces, is that classification supported by the external evidence? |

**Calibration is the one that makes the rest honest.** Without it, Legasus can achieve beautiful commit
precision by becoming an increasingly sophisticated refusal machine. A refusal is only correct if the
external evidence supports the specific reason given.

## Verdict classes

    AGREEMENT                  same subject, compatible scope, same conclusion
    EXPLAINED INCOMPATIBILITY  provenance, scope or referent accounts for the difference
    GENUINE_CONTEST            same subject, compatible scope, both entitled, conclusions conflict
    INSUFFICIENT EVIDENCE      one side never earned the right to speak
    QUIESCENCE                 no justified operation is expected to change what may be claimed

`NOT_COMPARABLE` is **reported separately and never scored as secretly correct.** Every use of it must
name which admitted dimension defeated the comparison, and that dimension's relevance argument must
predate Repo C.

**A genuine contest is not required to occur.** If the corpus contains none, that is `0 observed` — not a
failure, and absolutely not something to manufacture. What is being tested is whether the architecture
*can* preserve one, which the freeze gate already establishes in the laboratory.

## THE BURN RULE

Once the first Repo C task runs:

> **A discovered architecture defect may be diagnosed and repaired, but that run is burned.**

It may not be patched mid-run and still called prospective. The record reads:

    Repo C @ legasus-freeze-r3  ->  failure
    cause                       ->  ...
    repair                      ->  development resumes
    Repo D @ legasus-freeze-r4  ->  the next prospective test

This discipline matters more now than it did at r2, precisely because the architecture has become good
enough at explanation to absorb a contradiction without anyone noticing it did.

## What is already known to be unresolved

Recorded here so it cannot later be presented as a discovery:

1. **The independent root is an axiom, not a constructor.** `delegate({from: OWNER})` mints without a prior
   token. Normative authority must enter from outside the system, so the calculus is three constructors
   *and one axiom*.
2. **Law 7 only half-reduces.** "No token, no action" follows from the calculus; the requirement that an
   investigation be able to change entitlement does not. It is a termination property, and conservation
   cannot supply it.
3. **The internal equivalence results share my authorship.** The shadow-graph layers and the frozen-56
   classifications were all written by me over days. Independent in mechanism, not in authorship.
4. **The external probe was partial.** CPython `doctest` agreement was 86% on failing sets and 100% on
   failure kind, with every disagreement located in the evidence layer rather than the algebra.
5. **5 of the frozen 56 `packaging` candidates are specification mutations**, not behavioural ones.
