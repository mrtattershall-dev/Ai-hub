# Investigation of the 25 unclean iterations reported at 18:39 UTC

The snapshot contains 25 failed iterations out of 333, with 26 non-ESM violations: 24 BROKEN files across 23 iterations, and two FALSEVERIFIED runs. Historical results remain in fuzz-out; fixes do not turn those old results into passing observations.

## Broken JavaScript

Affected seeds: 100102, 100131, 100142, 100181, 100184, 100212, 100216, 100217, 100220, 100221, 100240, 100242, 100253, 100256, 100262, 100277, 100296, 100300, 100301, 100371, 100400, 100410, 100412. Seed 100400 broke both p1_calc.js and q3_list.js.

All 24 file cases have a recorded edit_file or append_file request that transforms a preserved, parsing version into invalid source. The common edit requests selected only `function add(a, b) {` or `function mul(a, b) {` in FIND but supplied an entire replacement function. Literal replacement correctly replaced that short header and left the old body below it, producing an extra closing brace. Other cases appended object-property fragments at top level or inserted a class method after the class had already closed. The defect was allowing the resulting invalid candidate to overwrite working source, not a reason to silently widen the requested edit region. The earlier append safeguard only rejected fragments creating a missing file. Existing-file edits/appends could still land corruption. End-of-run repair cannot always restore a parsing version while respecting its restriction against taking work from an earlier goal.

Fix: parse each JavaScript candidate in memory before write_file, edit_file or append_file can write it or issue a governed receipt. Rejection preserves the existing bytes, including on line-range and symbol-addressed edit paths, because they all pass through the same write boundary. Missing files are not created on refusal. CommonJS and module syntax are supported without executing generated code or spawning a host parser inside the workspace. Other file types retain their existing checks. The emergency rollback policy and its goal boundary are unchanged.

The 24 fixtures in server/testdata/fuzz-write-regressions.json come from recorded tool arguments and preserved Git file versions. sourceSyntax.test.mjs demonstrates the destructive operation with AGENT_SOURCE_SYNTAX=0, then replays it with admission enabled and verifies byte-for-byte preservation. Valid writes, edits, appends and module syntax are positive controls. Admission is enabled by default; the off switch is retained for historical diagnostic controls.

## False verification

Seeds 100408 and 100414 recorded Verified despite their last node test_q1_math.js exiting 1. The operational fuzzer inherited no AGENT_FINISH_EVIDENCE flag, while the governed launcher and live collector explicitly enabled it. Its invariant correctly flagged the older gate configuration; these two observations do not show that the live collector's enabled safeguard was bypassed.

Fix: default the operational replay harness to the enabled finish-evidence policy and explicitly export it in the unattended profile. An explicit off setting remains available for the existing historical control test. New fuzz details record both source-syntax admission and finish-evidence settings. finishEvidence.test.mjs exercises failed and passing self-tests through real isolated hubs, with the safeguard both enabled and disabled.

## Validation and rollout

The pure source-admission regression reproduces and prevents all 24 recorded corrupting transitions. The one-shot server/recheckFuzzFailures.mjs job runs related suites and the 25 exact historical seeds in fresh temporary hubs. By default it uses the shared heavy-job lock and unloads Ollama only after gaining that lock. For this investigation the mock-only worker runs alongside inference in a separate cgroup capped at 768 MiB RAM, 1 GiB swap, and one CPU thread, with a 384 MiB soft RAM limit. The first checks used a half-thread CPU cap, raised to one after confirming eight available CPU threads and roughly two used by Ollama. This mode refuses to start unless those caps are present; it never unloads or calls the real local model. The broad fuzzer and queued Inspector are deferred until verification finishes, then restored. Recheck outputs are separate under data/inspector/fuzz-repair-20261021.

The live 4B run is not restarted. New hub processes pick up source admission by default, and newly launched operational fuzz iterations enable finish evidence. Existing hubs load the source change when they next restart or a collector session creates its next isolated hub.

Final result: all 25 historical seeds passed the original non-ESM invariant metric, including both FALSEVERIFIED seeds. All seven related suites passed. The expanded sourceSyntax test also checks line-range and occurrence-selected edits. Source hashes were checked against the verification snapshot. The capped worker peaked at about 385 MiB RAM and 158 MiB swap. The live 4B collector progressed from goal 1 through goal 3 without being restarted. See 2026-10-21_RECHECK.json for the per-seed results.
