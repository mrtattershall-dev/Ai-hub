# Closure status replaces "proof complexity" in the working vocabulary (2026-09-21)

Earned by REACH-1 (c43fef3), which falsified both proxies I had used, in sequence:

    call-hop radius        falsified: a single radius carries all three verdicts; REACHABLE spans
                           1..9 and UNKNOWN spans 0..9
    minimal slice size     falsified, and backwards: UNKNOWN closures had median 0 definitions
                           against 7-8 for settled ones

## The distinction, stated in the form the data supports

> **Reachability difficulty is determined by the nature of the unresolved dependency, not by its
> structural distance from the decision.**

Operationally:

> **The relevant property of a reachability proof is whether its dependency closure terminates in
> admitted grounds — not how many edges it traverses.**

So the recorded quantity is a **proof frontier** with a near-binary status and a terminal class
carried alongside it:

    CLOSED   every required dependency terminates in admitted grounds
    OPEN     at least one required dependency terminates outside the admitted trust base

    terminal classes observed: TRUSTED PRIMITIVE, LITERAL/DEFAULT, KNOWN CONSTRAINT,
                               ENVIRONMENT, REFLECTION, EXTERNAL CALL, DYNAMIC DISPATCH,
                               UNKNOWN PRODUCER

A two-fact proof can be impossible (`caller -> environment -> UNKNOWN`) while an eighteen-fact
proof is straightforward if every edge lands on ground. **A proof is not weak because it is long.
It is weak because it remains open.**

This is why `UNKNOWN` alone is not a serializable verdict. It must be `UNKNOWN(reason)`, or the
system has discarded the one distinction needed to know why the proof stopped — the same shape as
`unmeasured`, `UNATTRIBUTED`, and `DISTINGUISHABLE`. The REACH-1 runner now asserts it.

## Scope of this claim

Supported across both frozen REACH-1 samples, on **one** target and **one** guard shape. Not
universal, and not proven for any analysis outside this branch. It replaces "proof complexity" as
the working vocabulary because both of its predecessors were falsified by measurement, not because
it has independent standing.

## H-EDGE — recorded, standing NONE, nothing installed

Some transformations **close** a dependency; others merely **move** it. `x = source() or "8.9"`
closes a branch of provenance: no upstream uncertainty survives that edge. `x = os.getenv("X")` is
one line away and leaves the proof open, because the environment sits outside the admitted grounds.

Candidate edge classification, untested:

    CLOSE     terminates the obligation in admitted grounds
    PRESERVE  forwards the obligation unchanged (parameter passing)
    EXPAND    multiplies the obligation (branching producers)
    OBSCURE   relocates the obligation outside the current model (dynamic lookup)

*Generated by the REACH-1 result. No prospective prediction, nothing installed.*

## The connection that is NOT yet earned

If H-NEUTRAL holds, a forced coercion of an unestablished state into an ordinary value may be doing
something worse than hiding a failure: it may be **artificially closing a proof obligation that
should have remained open**.

    OPEN dependency -> forced closure -> neutral value -> pipeline continues

That would connect reachability, H-INFO, H-TOTAL and H-NEUTRAL in a way none of them earns
individually, which is exactly why it is written here as a conditional and not as a finding.
H-NEUTRAL has not been run.
