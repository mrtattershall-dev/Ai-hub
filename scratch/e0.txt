THE ONE STRUCTURAL RULE THE MODULE EXISTS FOR: THE CHECK AND THE WRITE CONSUME THE SAME RESOLVED TARGET.
resolvedTarget is computed once and is the only value passed to both the authorization comparison and
writeFileSync. The baseline probe demonstrated the trap directly - it passed action: 'edit OTHER.js' as a
STRING while nothing derived a path from it - and an enforcement point that validates a label while
another argument picks the file would recreate the hole with a check in front of it. The comparison is
against the path RELATIVE TO ROOT, not the basename, or sub/fixture.js would satisfy a grant pinned to
fixture.js.
