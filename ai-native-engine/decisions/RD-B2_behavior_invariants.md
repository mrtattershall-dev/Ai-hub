# RD-B2: Behavior Invariants (Closed) — the checks that make AI-authored logic bear data-grade guarantees

**Question:** RD-B1 chose the representation (declarative rules). What invariants must surround it so behavior inherits everything the data layer proved — and which of the plan's proposed invariants turn out to be *unnecessary by construction*?

## Method
Each invariant implemented in the core (`core/engine.js`, `core/behavior.js`), proven in `experiments/026_behavior_invariants/behavior_invariants.js` (24 assertions) **with the project's signature negative control per invariant** — turn the guard off and the exact corruption it prevents reappears — plus a behavior fuzzer extending RD-021 to logic.

## Proven (measured)

- **I1 RANGE is now an ENGINE invariant** (closing RD-B1/A5, the FIELD_OWNER pattern recurring): a resolved value outside its field's typed-array range — or a non-integer on an int field — is rejected for **every contributing tx**, never truncated/clamped. Checked on the **resolved (post-fold) value**, so an additive fold whose *sum* overflows (3e9+2e9 on a uint32) is caught even when each contribution alone is in range. **Control:** guard off → the Uint8 pool silently wraps 999→231.
- **I2 OP BUDGET** (`opts.opsBudget`, default 2048): an oversized tx is rejected **whole** (atomicity — truncating a behavior is corruption), other txs in the tick untouched (isolation). Bounds per-tick work from any caller — player, AI wire, or a system. **Control:** budget off → a 150-op flood commits wholesale.
- **I3 CAPACITY**: `spawn()` past the row budget throws loudly; `createChild` past it is rejected with a localized reason, **counting creates staged in the same batch**. **Control (the pre-fix path):** an unchecked `count++` past capacity creates a **ghost entity** — OOB typed-array writes are silently ignored, so `byUuid` says live while every field reads garbage. A real hole found by writing the invariant.
- **I4 THE DOUBLE-BUFFER SUBSUMES HAZARD ANALYSIS** (the plan's "declared read/write sets" invariant is **unnecessary — measured, not assumed**): every system reads the same committed pre-tick state, so a read-after-write hazard between same-tick systems is *unrepresentable by construction*. Proven with a reads-what-the-other-writes rule pair (wilt reads water, irrigate writes it): committed state identical under both registration orders, and wilt provably read the pre-tick value. Same-field write collisions are already RD-005's fold/defer job. **No new scheduler machinery was built — the honest RD-005.3-style result ("the boundary was already right").**
- **W BEHAVIOR WIRE** (`core/behavior.js`, RD-B1 productized): `parseRule(engine, json)` → safe registerable system or localized `{rule, where, code, detail}` errors (malformed JSON included); `installRule` never registers a rejected rule. **Grammar extension: bounded `count(type, where)` aggregation closes RD-B1's R8 ceiling** — expressible, statically checked, interval `[0, capacity]`. The range proof is **capacity-aware and exact, not paranoid**: `count` into a Uint8 field is *accepted* on a 128-cap world (provably ≤128) and *rejected* on a 512-cap world — both measured.
- **I5 BEHAVIOR FUZZ (RD-021 extended to logic):** random worlds × random rule-sets (~3 rules/iter; ~15% iterations inject an invalid rule, all rejected at parse) × 5 ticks × **3 replicas each** — (A) generated order, (B) reversed registration order, (C) mid-run save/load — checking committed-state identity across order and across the persistence roundtrip, index consistency + identity coherence every tick, **bounded growth** (≤ Σ spawn-caps × ticks), and full undo/redo round-trip. Clean at 2k; **at 20k it failed twice — and found I6.** Post-fix: **20,000 iterations (60,002 rules, 3,086 injected-invalid all rejected) — ALL properties hold.**
- **I6 SYSTEM IDENTITY (found by scaling the fuzzer 2k→20k):** two generated rules collided on their 4-digit name suffix (probability ~1.7 per 20k — invisible at 2k). A system's name is its **actor id**, and RD-003 determinism is *cross-actor*: same-actor txs tie-break by input position, so two same-named rules made committed state silently depend on registration order. Diagnosis split honestly (the RD-021 discipline): the collision was a **fuzzer bug** (an invalid configuration — two systems claiming one identity), *and* it exposed an **engine gap** — `registerSystem` silently accepted the duplicate. Fixed on both sides: the engine throws on duplicate names (unrepresentable), the wire returns a localized `duplicate_name` error, the generator makes names unique by construction. Repro: `experiments/026_behavior_invariants/repro_11984.js`.

## Decision
- Behavior executes only through rules compiled to phase-0 systems; the engine backstops with **range / op-budget / capacity** invariants (defense in depth below the wire's earlier, better-localized rejections — the RD-018 two-layer split, now for logic).
- **Reject-whole over truncate-to-fit** everywhere: a partially-applied behavior is corruption, not a degraded success.
- **No read/write-set declarations, no hazard scheduler**: the pre-tick read discipline makes the hazard class unrepresentable. Complexity avoided is correctness gained.

## Transferable principle
Before building an analyzer for a failure class, check whether the execution model can make the class *unrepresentable* — a hazard that cannot be written needs no hazard detector. And when a guard must exist, verify it with its own absence: if turning it off doesn't reproduce the corruption, the guard wasn't load-bearing.

## What remains open
- Global per-tick op budget across ALL txs (per-tx budget bounds each actor; a thousand actors is a different attack) — flagged, not built.
- `count` is the only aggregation; `sum`/`nearest`/spatial predicates are future grammar cards (same static discipline).
- Rule *lifecycle* (uninstall, persistence of installed rules with the snapshot, rule versioning) — currently rules live outside the saved world, like claims/history. RD-B3's live loop will surface whether that's right.
- The live-model question (can a real model emit valid rule-IR; do localized rule errors teach it) → RD-B3.
