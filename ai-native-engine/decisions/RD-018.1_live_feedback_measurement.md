# RD-018.1: Live-Model Feedback — the Measurement (addendum to RD-014 / RD-018)

**The question both left explicitly open** (because it needs a real model): does handing a model its own LOCALIZED validator errors actually make its next proposal better, or does it flail either way?

**Now measured.** Model: `meta-llama/llama-3.2-1b-instruct` (via OpenRouter, temp 0.7 — a genuinely weak model, deliberately, so the effect is visible). Harness: `core/live_loop.js` + `core/live_loop_real.js`. Two arms, identical model/goals/budget/temperature; the ONLY difference is whether the re-prompt includes the localized errors + the model's prior attempt (FEEDBACK) or not (CONTROL). 4 machine-checkable goals × 5 trials × maxAttempts 5. Stable across three runs (12- and two 20-trial).

## Result (20 trials/arm, representative)

| goal | CONTROL | FEEDBACK | mean attempts (feedback) |
|---|---|---|---|
| setfield (water ≤ 80) | 0/5 | 5/5 | 2.0 |
| delete | 0/5 | 5/5 | 2.0 |
| setfield (growth = 100) | 0/5 | 5/5 | 2.0 |
| createChild (named crop) | 0/5 | 0/5 | — |
| **TOTAL** | **0% (0/20)** | **75% (15/20)** | **2.0** |

## Findings (measured, honest — including the ones that undercut a clean story)

1. **Localized feedback is decisive for a weak model.** 0% → 75%. CONTROL got the same 5 attempts and still never succeeded — the difference is purely the error content, not the extra tries. Successes land in a mean of **2.0 attempts** = exactly one repair round.
2. **The model gets CONTENT right, STRUCTURE wrong.** Its dominant one-shot failure is emitting a bare op — `{"op":"setfield","target":"u1","field":"water","value":80}` — with the correct field and value, but missing the `{"actor","ops":[...]}` envelope. Naming that specific error fixes it in one round. This is direct support for RD-014's thesis: the deterministic gate is load-bearing; the model is a swappable proposer that good errors make *competent*, not just safe.
3. **Feedback is not a panacea (createChild stays 0%).** On the hardest goal the 1B *degenerates* under feedback: token-repetition loops (`"cropType":"zone"` ×N → truncated → invalid JSON) and copying grammar placeholders literally. Localized errors help when the fix is a small structural nudge the model can execute — not when the model cannot represent the target at all.
4. **Validator-ERROR-TEXT is as load-bearing as the loop.** With a bare `missing "ops" array`, feedback stayed at 0%. Rewriting it to *diagnose the actual mistake* — `you emitted a single bare op; it must go inside an "ops" array. expected shape: {...}` — is what unlocked the 0%→75%. The value is in the specificity, not the mere presence of an error. (This upgraded `protocol.js`'s `no_ops`/`not_object` messages — a measurement-driven fix.)
5. **Prompt verbosity BACKFIRES for a 1B (counterintuitive, measured).** Replacing the concise grammar with a longer, "clearer" one (prose choices + a worked example per op) DROPPED success 75% → 20%. Short won. Prompt effects on a small model are large and non-monotonic; "more explicit" is not "better". The concise grammar is kept for this reason.

## Reading
For a weak local proposer, the RD-018 structured-IR wire + RD-014 contract gate is not just a safety boundary — its *localized errors are the mechanism that makes the proposer usable at all*. A 1B that succeeds 0% of the time alone succeeds 75% when the validator tells it precisely what to fix, in one repair round. The boundary doesn't just reject bad output; it teaches a weak model to produce good output.

## Capability curve — 3 models (added; the feedback effect is capability-dependent)

| model | backend | CONTROL (≈one-shot) | FEEDBACK | note |
|---|---|---|---|---|
| llama-3.2-1b | OpenRouter | **0%** (0/20) | **75%** (15/20) | can't emit valid IR alone; feedback RESCUES it (fixes the missing ops-envelope in 1 round) |
| qwen2.5-coder-7b | **local Ollama** | **~75%** (3/4) | **~75%** (3/4) | largely one-shots the IR incl. createChild; feedback neither needed nor harmful |
| gpt-oss-20b | OpenRouter (`:free`) | one-shots all reached incl. createChild | — | fully capable; free tier daily-capped so no clean 2-arm run |

**Shape:** the localized-feedback benefit is LARGE for a model too weak to produce valid structured output (1B: +75 pts) and vanishes as capability rises (7B: ~0; 20B: doesn't need it). The validator boundary is a crutch for weak proposers and a no-op cost for strong ones — which is the right property: it makes a cheap local 1B *usable* without penalising a capable model.

**7B FIRMED UP ON GPU (Modal, Qwen2.5-Coder-7B via transformers, 4 trials/goal):** CONTROL **100% (16/16)**, FEEDBACK 94% (15/16) — the 7B ONE-SHOTS essentially everything, including createChild. The earlier local n=1 (~75%) was just noise; the real 7B is fully capable, so feedback is irrelevant-to-slightly-negative for it (within n=4 noise). Confirms the curve shape: feedback rescues the weak 1B (0%→75%), no-op for capable models. `experiments/023_model_capability_curve/`.

**Honesty caveats on the (original) 7B/20B rows:** the local 7B row was n=1 per cell — superseded by the GPU run above. The 20B row is salvaged from rate-limit-contaminated runs (free tier = 50 req/day), NOT a clean battery — reported as directional only. `core/live_loop_real.js` now supports a local Ollama backend (`OLLAMA_MODEL=...`, no tunnel/rental — the harness runs on the model's machine) with robust balanced-brace JSON extraction. Windows gotcha: the `TEMP` env var collides with %TEMP%; use a different knob name.

## Open (prompt-design cards this surfaced)
- The `A|B|C` placeholder in the concise grammar is sometimes copied literally on createChild; a fix that stays concise (the verbose fix regressed everything) is unfound.
- createChild resistance: a 1B may need op-type-specific scaffolding (or a constrained-decoding / grammar-sampling backend) rather than more prose.
- Only one model, one temperature, 4 goals. A stronger local model (3B/7B) and more goals would sharpen where the feedback curve saturates.
- Blind CONTROL used the same temperature; a "resample-only" control at higher temperature might close some gap — untested.
