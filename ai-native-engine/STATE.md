2. Object identity — UUID vs content-hash vs path — **RD-004 DECIDED: UUID**

Serialization/storage — JSON vs binary vs event log — **RD-019 DECIDED (MEASURED): persist authoritative state + the uuid high-water counter; REBUILD derived indexes on load; SNAPSHOT not log-replay. `core/persistence.js`. - **RD-017** index consistency under transactions (MEASURED) → **derived indexes are transactional state, STAGED and committed atomically with the data.** Three rival couplings checked against a ground-truth oracle (indexes rebuilt from committed data). **EAGER (in-place index writes, roll back only data) INADMISSIBLE** — leaks aborted ops' index entries, `who references Z?` returns a stale-index lie, diverges at the first rejected tx in a 200-tx stress mix — the project's core silent-corruption failure reappearing at the index layer. **REBUILD admissible but O(N) per commit; STAGED wins** — correct AND O(change-size) (3 writes vs REBUILD's 7=N). Eager index maintenance forbidden wherever a tx can reject after touching an index. `experiments/017_index_transactions/`, `decisions/RD-017_index_transactions.md`.
- **RD-020** history/undo (MEASURED, spine #9) → **inverse-delta undo/redo, linear history.** Rival snapshot-per-step is O(N)/step; winner records only the change + how to reverse it (O(change)) — 50 single-field edits = 50 inverse entries vs 10,050 entity-copies for snapshots (>100×). Identity preserved: delete-undo **resurrects the SAME uuid** + reconnects referrers (works because delete only tombstones, never clears the row); create-undo re-tombstones and never recycles (RD-004.6). Every undo/redo rebuilds indexes via the RD-019 stale-proof rebuild → `indexesConsistent()` always holds. New edit after undo clears redo (linear). History is ephemeral (not persisted, like claims). `Engine.enableHistory()/undo()/redo()`, `core/history_test.js` (26/26), `decisions/RD-020_history_undo.md`. Open: branching history, cross-session undo, compaction.
- **RD-019** persistence/serialization (MEASURED, spine #3) → **snapshot of AUTHORITATIVE state only + preserve the uuid high-water counter; rebuild derived indexes on load.** Rival that persists indexes + resets the counter FAILS twice: (1) reset-counter RECYCLES a tombstoned uuid on next spawn → stale ref silently resolves live (RD-004/004.6 freelist bug via save/load); (2) a stored index can be stale/tampered → loads a SILENT LIE (RD-017 failure at storage). Winner immune by construction (no stored index; counter preserved). Snapshot over log-replay for persistence (O(live+tombstones) vs O(all history)); the log is the UNDO substrate (#9). `core/persistence.js`, `core/persistence_test.js` (18/18), `decisions/RD-019_persistence.md`.
- **RD-019.1** tombstone GC (MEASURED) → **reference-counted: drop a tombstone iff no live entity references its uuid (refs[] or dangling parent).** Closes RD-019's open cost. NEVER = unbounded; EAGER/HardDelete drops deleted-vs-missing metadata while still reachable (RD-004.6 re-confirmed); REFCNT keeps metadata exactly while a live ref points at it, then reclaims. Corruption-safe unconditionally (uuids never recycle → dropped uuid resolves `missing`, never wrong-live). Composes with persistence + indexes; GC-then-undo verified safe. `Engine.gcTombstones()`, `core/tombstone_gc_test.js` (18/18), `decisions/RD-019.1_tombstone_gc.md`. Open: in-world reachability only (external refs need a retain-flag/registry), incremental refcount.
