# Phaser data defect — measured, root-caused, gated

**Date:** 2026-09-08 · **Model under test:** `mycoder-v0.2` (run3 adapter, Qwen2.5-Coder-14B QLoRA)
**Instrument:** every generated program executed in real headless Chromium via the hub's
`/api/game/verify` (engine loaded? canvas created with non-zero size? anything thrown?).

---

## 1. The measurement

12 prompts (6 concrete "correctness", 6 vague "comprehension"), generated by the served
model, each executed in Chromium.

| Intervention | correctness | comprehension | overall | still loaded assets |
|---|---|---|---|---|
| none (baseline) | 0/6 | 0/6 | **0/12** | 11/12 |
| explicit "never load external assets" | 2/6 | 0/6 | 2/12 | 10/12 |
| one-shot: a complete working asset-free program | 2/6 | — | — | 4/6 |

**11 of 12 baseline failures shared one root cause: a missing asset.**

The plateau is the finding. A direct prohibition and a full worked exemplar — two very
different intervention strengths — both land on exactly 2/6. When showing the model the
answer does not beat telling it, the behaviour is not being retrieved from context; it is
in the weights. **No prompt-level fix exists for this.**

## 2. Root cause

`dataset_run4.jsonl`, Phaser slice (4,242 rows = 41% of the set):

| pattern | rows | share |
|---|---|---|
| `this.load.image(...)` etc. | 3,034 | 71% |
| `assets/` paths | 3,122 | 73% |
| `phaserfiles.com` CDN | 2,970 | 70% |
| `parent: 'phaser-example'` | 4,038 | 95% |
| generated graphics instead | 1,086 | 25% |

The slice was harvested from Phaser's official examples, which are correct **on a site that
serves assets**. `harvest_phaser.mjs` deliberately skipped the free-var gate and trusted them
"as-is" — three checks (parse, size, dedup) where every other slice gets the full gate. The
model reproduced the convention faithfully, including a commented-out `setBaseURL` line.

This is `INVARIANTS.md`'s thesis in the training pipeline: **portability was true by
convention (the examples' home server satisfied it), never by construction or enforcement.**

## 3. A second defect class, only visible by executing

Static filtering removes asset-dependent rows: 4,242 → 1,072. But only **~54%** of the
survivors actually render. The rest are **fragments** — helper functions and partial scene
classes from a repo organised by API rather than by whole program. They parse, load nothing,
and create no canvas. A static gate cannot see this; execution can.

Expected end state: **~580 proven-rendering Phaser rows** from 4,242.

## 4. What was changed

- `gate.mjs` — new `dependsOnExternalResources()`: rejects asset loads, `setBaseURL`, the
  Phaser CDN, `assets/` paths, remote image/fetch URLs. Allows self-contained `data:` URIs.
- `harvest_phaser.mjs` — now runs that gate. The defect cannot re-enter from a new harvest.
- `filter_assets.mjs` — static pass, non-destructive.
- `verify_dataset.mjs` — score any dataset by execution *before* training on it.
- `build_verified.mjs` — keep only rows proven to render; resumable via a verdicts sidecar.
- Hub Game prompt — anti-asset instruction as a measured stopgap (0/6 → 2/6).

## 5. Open

- **Regenerate the Phaser slice.** ~580 verified rows is trustworthy but too small; volume
  must be rebuilt with generated-graphics code, Chromium-gated per row. Costs GPU.
- **run4 will not fix this.** It trains on the same 4,242 Phaser rows. Its 6,099 added
  comprehension rows also carry a *different system prompt*, so gains may not transfer into
  Phaser mode at all. Evaluate against the 0/12 baseline before concluding anything.
